# License, art and brand

This page answers three questions that are usually answered wrong, and by different
files: **what holds today**, **how the change was applied**, and **who
needed to agree** for it to happen.

:::danger This page does not change the license
It **documents**. As long as `LICENSE` says what it says in the block below, that is what
holds — here and in every other file in the repository. No file may **declare** the
future license before `LICENSE` does.
:::

## The migration to AGPL-3.0, applied on 07/08/2026 {#decided-and-pending-agpl}

The project started out **MIT** and has been **AGPL-3.0** since **2026-08-07**, applied in
commit [`3f7a9be`](https://github.com/rubenmarcus/csbrasil/commit/3f7a9be) — all eight
surfaces in a single commit, exactly as this page demanded before the switch happened. The
decision reverses an earlier recommendation from the repository itself (`plans/06 §1.2`
argued for staying permissive because of Steamworks and of AI credit programs).

The reason for the turnaround is in [`plans/08 §3`](https://github.com/rubenmarcus/csbrasil/blob/main/plans/08-RELEASE-PROFISSIONAL.md):
the project intends to **sell skins and maps**, and selling items changes the threat model.
The AGPL **does not prevent** selling — you sell the right of use — but it is honest about
what it does not solve: anyone can publish a fork with the ownership gate removed,
**legally**. That is the reason the real protection is server-side, not the license.

### Why earlier contributors did not have to consent {#not-done-yet}

This was the task the doc announced as blocking, and **it was framed wrong**. The consent
rule applies to relicensing a third party's contribution under terms the original license
does not authorize. That is not the case here:

- **MIT is permissive and compatible with the AGPL.** It authorizes sublicensing and
  incorporating the code into a work distributed under other terms, as long as the original
  copyright notice stays in the package.
- So **whatever came in before 2026-08-07 remains MIT inside the whole**, and the whole is
  distributed under AGPL-3.0. Nobody who contributed earlier loses anything, and nobody had
  to approve it.
- The **incompatible** direction is the reverse — taking a third party's AGPL code and
  redistributing it under MIT. That one would require consent from every author, and it is
  why the switch is **one-way in practice**.

:::note This is the project's reading, not legal advice
MIT → AGPL compatibility is old, comfortable consensus in the ecosystem, but if your
contribution carries a specific employer or client requirement, **ask before opening the
PR** instead of assuming.
:::

### Who signs the published history {#who-signs}

The survey is still useful for another reason — knowing whose code this is — and it is
measured, not estimated:

```bash
git shortlog -sne --no-merges origin/main   # who signs the published history
gh pr list --state merged --limit 50        # what came in, and from whom
```

On **2026-08-05**, the published history (`origin/main`) has **two third-party
contributors with merged work**:

| Who | What came in | Where |
|---|---|---|
| `daltonfontes` | the `piscina_treta` map ("Piscinão da Treta"), 1 commit | is on this branch |
| **William Oliveira** (`@woliveiras`) | the **Godot desktop client**, 13 commits, PR #14 merged on 18/07/2026 | **`main` — not on this branch** |

:::caution The working branch's `git shortlog` does NOT enumerate the project's contributors
The people block in [How to contribute](./colaborar.md) measures **HEAD**, and HEAD is a
branch. `v2/alpha` branched off `main` **before** the merge of PR #14, so William's 13
commits do not appear on it — and the doc was announcing three people in a repository that
has four. For any decision about the license, **measure against `origin/main`**, not
against the branch you are working on. See the [Roadmap](https://github.com/rubenmarcus/csbrasil/blob/main/docs/ROADMAP.md),
section on the divergence between `main` and `v2/alpha`.
:::

The repository is **public** and has stars (`gh repo view --json stargazerCount`), which
means **copies of the code under MIT already exist**, made before 2026-08-07. **That is
irreversible:** git history keeps the permissive version forever, and a fork made under the
old license stays under it. The AGPL governs what leaves here **from now on** — it does not
recall what already left.

### The points that changed together {#points-that-change-together}

All of this went in a single commit, and it is the list any future switch has to repeat:

1. the `LICENSE` file;
2. the badge at the top of `README.md`;
3. the license section of `README.md` (a generated block — just run `npm run docs`);
4. the term the contributor accepts, in `CONTRIBUTING.md`;
5. the site footer (`src/layouts/Layout.astro`);
6. the game's JSON-LD (`src/pages/index.astro`) and the `/sobre` page;
7. `public/llms.txt` and the footer of this documentation.

The generated table above is the always-current version of this list — the line numbers
come from it, and not from this paragraph. **Half a license switch is worse than none**,
because each file starts answering something different to whoever asks.

:::caution What a license switch does NOT do on its own: publish
The commit changed the files. The published doc kept saying `MIT` for three days, because
`docs/` is a **built** site — and nobody had run the build after the migration. Changing
eight surfaces in one commit is pointless if the ninth, the page the public reads, is a
static copy of the old state:

```bash
cd docs && npm run build:site   # rewrites public/docs/ — that is what goes live
```

Worse: `tools/gen-docs.mjs` **did not recognize** the new `LICENSE` (the official AGPL text
never contains the `AGPL-3.0` identifier in its header) and, instead of going red, returned
`null` and wrote coherent prose on top of nothing. Both are fixed: the name comes from the
license **title**, is checked against the `license` field of `package.json`, and **failing
to identify it now fails `docs:check`** instead of publishing a `null`.
:::

## The separation almost nobody knows about: code × art × brand {#code-art-brand}

This is the decision in [`plans/08 §3`](https://github.com/rubenmarcus/csbrasil/blob/main/plans/08-RELEASE-PROFISSIONAL.md)
that makes the rest possible, and it is **three different licenses for three different things**:

| Layer | What it is | Regime | Where it lives |
|---|---|---|---|
| **Code** | engine, base maps, UI, the entire harness | **open** (AGPL-3.0) | public repository |
| **Paid art** | skins, maps and items that are sold | **its own license, proprietary** | **outside** the public repository, under authorization |
| **Brand** | "CORO SOLTO: Treta Suprema", the canarinho, the logo | **not licensed** | nobody's but the owner's |

This is what makes it possible to **sell skins without locking the code**. The code stays
open and auditable; what is sold is art, which was never under the code's license; and the
name does not go along — a legal fork of the engine is not CORO SOLTO, because the brand
was not licensed.

:::danger This is irreversible once the first paid art exists
The character GLBs **are already in the public repository** (the count is in the generated
block of [Getting started](./comecando.md)). If one of them becomes a paid item,
relicensing is retroactive and git history keeps the free version forever.

**The decision about where paid art lives has to be made BEFORE the first paid art
exists.** After that, the cost is not editing a `LICENSE`: it is accepting that the sold
item has already been distributed for free.
:::

And the uncomfortable truth, written down so it is not rediscovered every round: **the
player can always make their own screen show any skin, and trying to prevent that costs
weeks and does not work.** The fraud that matters is obtaining the file without paying and
showing up with it **to the others** — and that one is server-side, like the
*entitlement*, which lives in Postgres under `service_role`. Spending effort on the client
is spending it in the wrong place.

## If you are going to contribute {#if-you-contribute}

The term that holds is in [`CONTRIBUTING.md`](https://github.com/rubenmarcus/csbrasil/blob/main/CONTRIBUTING.md),
and it is the source — this page does not repeat it. The operational summary: you license
under whatever license `LICENSE` says **at the moment of your PR** — today, **AGPL-3.0** —,
any future switch will come in a single, announced commit, and if that is decisive for you,
**ask before opening the PR**.
